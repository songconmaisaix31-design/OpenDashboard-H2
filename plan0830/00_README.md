## §1 迭代定位与边界

1. **起点**：plan0829 全部任务线已闭环并冻结"可交付"（2026-08-30，tag `gate-s6`，main 已合并）。本轮不是补漏轮，而是**冲分轮**：在"可交付"基础上，针对可见评分面与盲测敞口做最后一轮精度、演示与合规提升。
2. **本轮四大目标**（用户 2026-08-30 确认，四方向全选）：
   - A 线：ML 检测与指标精度（事件级 P/R/F1、检测时效、影响量化对齐）
   - B 线：运维助手 LLM 质量（StepFun 收尾、Q01-Q10 现场问答、语料与追问）
   - C 线：前端演示与可视化（18 分表逐项对标、演示脚本、企业价值物料）
   - D 线：部署交付与验收合规（换机复现 4 分、submission 收口、质量扩展、外联）
3. **边界继承 plan0829 §1**：所有判据改动必须①可解释（变量+时间窗+判断依据三要素）；②过哨兵门禁（F1 不回退超容差、N01-N07 误报不升）。
4. **执行纪律**：优先快速开发功能、压缩测试环节——验收以现有 `validation/` 脚本冒烟 + 截图/清单留痕为主，新增断言 <100 行/任务，不引新测试框架，不破坏既有门禁。

## §2 评分面事实模型（不变，沿用 plan0829 §2 并更新）

- **可见评分仅 18 分**（xlsx「Web 验收」sheet）：系统总览 4 ｜ 事件中心 4 ｜ 运维助手 4（**现场问答**）｜ 报告 2 ｜ 部署 4（**换机复现**）。
- **需求书本地副本仍缺第 8-10、13 节**（D01-D13 交付物清单 + 完整评分框架不可得）；D-P0-3 继续外联确认。
- **方法论**：隐藏评分不可测 → 按「18 分可见分 + 验收-T01~T14 条款 + 风险覆盖」三轴排优先级；任何排序不代表官方权重。
- **检测时效硬指标**（detection_expectation 全 350 条同一句）：C05/C07 须**提前预警**（事件开始前）；其余五类**开始后 10 分钟内**检出。
- **本轮新增评分敞口认知**（2026-08-30 三线探索结论）：
  - test 分区 16 条操作日志 = 盲测独立触发先验（5 类操作→C 码映射，见 A-P0-1）
  - severity 可由 anomaly_code 唯一推出（提交一致性冗余列，见 A-P0-3）
  - 报警 14 关联码可作弱特征（泄漏已降级，仅置信增强，见 A-P0-2）
  - N0k↔C0k 一一镜像；N05/N07 是提前预警主误报源

## §8 变更纪律与安全红线（全员必读，继承 plan0829 §6）

1. **SHA 证据只对 clean commit 有效**：文档提交改变候选 SHA → 提交后必须重生成 ignored 证据。
2. `packages/h2-contracts` 与 `packages/h2-vocabulary` 是唯一事实源：改契约/词表必须过 `npm run h2:qa`；冻结 JSON 只允许加版本号与新增可选字段。
3. `detection-thresholds.json` 仅 A 线可改，且必须版本递增（v5→v6）+ 算法三件套（独立 commit+阈值快照+四项指标对照）。
4. 回退总开关：`H2_ML_ENABLED=false`（检测）、`STEPFUN_API_KEY` 不注入（助手）→ 回到纯确定性系统。
5. 口径疑问一律登记 `D/ENTERPRISE_OUTREACH.md`，走保守默认口径，不阻塞开发；禁止任何"按企业要求"表述。
6. **安全红线不因迭代松动**：local-first/loopback-only、不发控制指令、建议必带人工确认、LLM 不触碰检测证据复核事实、不构造电解槽健康度、不硬编码测试答案、不凭 system_alarm_count 判异常。
