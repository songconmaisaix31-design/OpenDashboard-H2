## §2 P0 六题逐题展开

### Q1 资料权威版本
- **问题原文**：本地 `00_需求书` 各格式均从第 7 节直接跳至第 11 节，缺第 8-10 节（含 13 类最终交付物 D01-D13 与建议交付目录）与第 13 节（评分框架）；且 `00/02/03` 三个文件与 `20_包文件校验清单_SHA256.txt` 不一致（21/24 匹配）。能否提供与校验清单一致的权威完整版？
- **为什么关键**：交付物清单与评分权重是全部优先级排序的最大未知项；缺节意味着算法分值不可见，只能防御性全覆盖。
- **保守口径**：按现有资料+防御性交付执行；不推导官方完成分。
- **答复到达的变更路径**：补发完整版 → 00_README 追溯矩阵按 D01-D13 重排交付核对表（整合人）；答复"以现有版为准" → 维持现状，台账关题。

### Q2 事件级官方评分规则
- **问题原文**：公开标签 `detection_expectation` 为"C05/C07 提前预警；其他事件开始后 10 分钟内发现"。正式评分如何匹配预测事件与标准事件（IoU/时间容差/首检延迟/拆分合并/一对多）？
- **为什么关键**：内部 `validation/lib/metrics.mjs`（贪心一对一+10 分钟宽限窗）是自定规则；任一差异都会改变指标口径与 A 线调参目标。
- **保守口径**：维持内部规则+多指标并行（F1+lead_time+10 分钟检出率）多角度覆盖。
- **答复到达的变更路径**：A 线评估器按官方规则适配（走 A 线变更+基线重冻结）；口径入 CONTRACTS。

### Q3 评分框架权重
- **问题原文**：第 13 节评分框架（各任务/交付物权重）能否提供？
- **为什么关键**：决定 P1/P2 相对排序与裁剪策略。
- **保守口径**：按「18 分可见分+验收-T01~T14+风险覆盖」排序，不引用任何自推权重。
- **答复到达的变更路径**：00_README 定量目标表重排（整合人）；各线裁剪序复审。

### Q4 submission 契约细节
- **问题原文**：`17_submission_template.csv` 仅 16 列表头。①时间戳格式与时区；②设备 token 规范（台账 `ELZ01/ELZ02/ELZ03/BESS01/PCC01` vs 标签中 `ELZ3,ELZ1,BESS,PCC` 以哪个为准）；③confidence 取值范围与语义；④evidence_json 结构约束；⑤pred_event_id 命名规则。
- **为什么关键**：affected_equipment 与标签写法不一致是真实歧义，直接影响 checker 与导出器（D-P0-2 硬门禁的对象）。
- **保守口径**：时间戳与输入同格式；token 归一化到台账 `*01` 形式并留痕；confidence 沿用 [0,1] 检测置信；evidence_json 保持现有结构；pred_event_id 用 `{code}-{YYYYMMDD}-{ordinal:03d}`。
- **答复到达的变更路径**：`submission-equipment-tokens.json`（冻结契约）经 change-request 更新 → D-P0-2 校验器同步 → check-submission 回归。

### Q7 现场问答网络条件
- **问题原文**：现场问答验收环境的网络条件？（我们引入可选云端 LLM 增强层，已设计离线降级链：无网自动切换本地模式，不影响验收。）
- **为什么关键**：直接决定 LLM 层是"现场可用"还是"仅演示价值"，影响 B-P0-2 三态策略与助手 4 分的呈现方式。
- **保守口径**：按"无网"设计与演练；LLM 作为增值不作依赖。
- **答复到达的变更路径**：有网 → B 线现场启用云端路径（须先按红线声明外部 API）+演示脚本主路径切换；无网 → 维持双路径演示段。任一答复都不破坏离线降级链。

### Q10 正式测试提交通道
- **问题原文**：正式测试集结果的提交通道、截止时间、次数限制与失败反馈机制？验收机环境（OS/CPU/内存/浏览器/是否可预装依赖）？
- **为什么关键**：决定交付包形态（离线 bundle 是否必需=D-P1-3 的前提）与换机演练环境矩阵（D-P0-1 的 4 分）。
- **保守口径**：按"换机独立环境+本地离线+一键启动"最严假设准备（runbook 覆盖 Windows/双端口/Node/Python 版本矩阵）。
- **答复到达的变更路径**：环境宽松 → RUNBOOK 环境矩阵收窄、离线包降级为可选项；通道确认 → HANDOFF 交付流程更新。

## §3 外联纪律

1. **节奏**：每轮最多 2-3 题（轮次见 §1 末表）；收到答复先复述求确认再入账。
2. **记录三分离**：「资料事实 / 企业原话 / 项目推断」分开记录；不问诱导性问题；不暗示企业背书。
3. **答复到达流程**：答复原文入 §1/§2 对应题 → 受影响优化项复核 → 口径变更走 **CONTRACTS 变更流程**（不静默改）→ 整合窗向各线周知 → 演示对策复核（C/B 线确认演示不受影响或给出切换预案）。
4. **违规表述清单**：任何对外或对内文档禁用「按企业要求」「经企业确认」指未获书面答复的口径；台账「答复状态」列只有「未答复 / 已外联 / 已获答复(日期) / 已闭环」四值。
5. **长期悬置**：外联零回复=保守口径即终态口径；每轮整合窗检查一次台账时效，G2 冻结时把终态口径汇总进 HANDOFF。
