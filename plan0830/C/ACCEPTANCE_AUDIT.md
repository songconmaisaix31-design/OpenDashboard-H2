## §2 使用说明

1. **首日（C-P0-1）**：`npm run h2:fixture` 启动逐页走查，填满「现状评估」列（写实，注明页面/文件依据；fixture/local 双模式差异备注）；截图入 `plan0830/C/evidence/C-P0-1/`，在末列引用编号。现状初判可引 `plan0829/01_GAP_ANALYSIS.md` §1 作起点，但须实测复核。
2. **负责任务收工时**：更新对应行——达标则「差距」列清空并标「已达标」，「证据与截图引用」补齐；部分达标写残余差距与承接卡。
3. **G1（D7）门禁**：全行必须有结论，三者居一——**达标 / 差距转 R2 任务（注明卡号）/ 明示放弃（附理由）**。本表是 G1 门禁判据之一（`../COORDINATION.md`）。
4. **G2（D14 冻结）**：目标全行达标或差距明示；整合人引用本表出冻结报告；截图终版晋升 `submission/h2-sentinel/screenshots/`。
5. **状态标记词汇统一**：达标 / 进行中 / 未开始 / 差距-转R2 / 差距-放弃（附理由）。禁止使用无定义标记。
6. 汇总行「已达标 x 分 / 进行中 y 分」仅统计 5 个有分值行（x+y ≤ 18）；门槛行不计分、只记结论。
