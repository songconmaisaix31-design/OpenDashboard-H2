## §2 两轮验证策略

- **R1（功能轮）验证重点**：每张 P0 卡自带验收命令全绿；I1/I2 整合窗 `check-all.mjs` 全绿；ACCEPTANCE_AUDIT 五行有现状结论；换机双演练完成并修复失败项。
- **R2（打磨轮）验证重点**：A 线若改阈值 → 77 窗 0 FP 重冻结 + detector_version 递增；Q01-Q10 样例集命中 ≥90%；三态切换演示通过；G2 终值复跑（check-all + run-demo 双次 <180s + 换机演练 + submission 样例）。
- **验证金字塔**：L1 本卡冒烟（每卡）→ L2 线内回归（每 P0 卡）→ L3 整合门禁（每整合窗）→ L4 冻结门禁（D14）；详见 COORDINATION §6。

## §3 回退策略（与 COORDINATION §7 一致）

1. 算法：`H2_ML_ENABLED=false` + 阈值回上一版本 + 基线重冻结。
2. 助手：`STEPFUN_API_KEY` 不注入 → 本地降级。
3. 整合：`git reset --hard gate-i(n-1)`。
4. 冻结：推迟 tag，砍至各线 P0 最小集。

## §4 防过拟合纪律（继承 plan0829，不松动）

1. 不得以任何方式在检测/聚合逻辑中硬编码测试集时间窗或事件数量（98 个事件数禁止写入代码）。
2. 先验/弱特征只能调整置信与排序，不得独立触发事件。
3. TRAIN/VAL 对账断言只用于公开分区；测试分区仅经导出管线触碰。
4. 哨兵（overfit-sentinel）对新增特征必须扩展覆盖（A-P2-2）。
