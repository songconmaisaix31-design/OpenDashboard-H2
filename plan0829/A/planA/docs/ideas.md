## 问答记录（上游已答，标注来源）

### 场景
- Q: 迭代优先级如何排？
  A: 「18 分可见分 + T01-T14 验收 + 风险覆盖」三轴；官方权重不可得（需求书缺第 8-10、13 节），不虚构（`../../00_README.md` §2）
### 核心功能
- Q: A 线做什么？
  A: 7 项 = P0-4 / P0-5 / P1-1 / P1-2 / P1-9 / P0-7 / P1-8（`../TASKS.md`）
### 数据与来源
- Q: 能用什么数据？
  A: 公开 train（280 事件，标签全开）+ validation（70 事件，可调参）；normal_context 77 条只作误报回归；**测试集仅最终一次性推理**（`../../02_ALGO_ROBUSTNESS.md` §9）
### 硬约束
- 双机协作（B 机并行，契约 `../COORDINATION.md`）；14 天日程；门禁一票否决；企业 0 答复走保守默认口径

## MVP 一句话

为参赛团队在 14 天内以"先建尺子、再改判据、最后 ML 灰度"的顺序完成 A 线 7 任务，最小可用版本包含：N01-N07 误报基线、C05/C07 提前预警可测、去签名带后 F1 不回退。
