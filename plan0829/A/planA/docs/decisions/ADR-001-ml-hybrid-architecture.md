# ADR-001 ML 混合采用"规则为主、ML 校验层 + 开关灰度"

- **日期**：2026-08-29 ｜ **状态**：已接受
- **背景**：规则引擎 F1=0.9718 但 C03/C05/C06 依赖 ±1kW 签名带（TRAIN 经验拟合）；`lightgbm_adapter.py` 已存在未接线；用户决策"全力引入 ML"。
- **选项**：
  1. 仅规则稳健化（风险最低但放弃上限）
  2. 规则为主 + ML 校验/补充层 + `H2_ML_ENABLED` 灰度开关（默认 false）
  3. 全 ML 替换（可解释红线不可过；adapter 显式拒绝 C01/C02/C06 动态归因）
- **理由**：选项 2 兼顾上限与回退安全；遵守项目铁律"模型检测 → 规则校验 → AI 解释 → 人工决策"；ML 覆盖 C03/C04/C05/C07 + 全类别二次评分，归因仍由规则负责。
- **被否方案**：选项 1（用户要求冲上限）、选项 3（违反可解释红线）。
- **后果**：需建 MODELS_REGISTRY 治理（产物不入库、SHA/参数登记）；灰度五条为一票否决；训练只用 train+validation。
