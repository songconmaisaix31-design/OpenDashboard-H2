## §1 迭代定位与边界声明

1. **P1 阶段边界正式解禁**：`docs/competition/h2-sentinel/P1_EXECUTION_SPEC.md` 曾规定"不做检测器扩展/C01-C07 算法扩展/阈值重调"。解禁理由：(a) 该边界针对 P1 交付稳定性，现在检测管线已有 169 pytest + 75 契约 QA + 过拟合哨兵三层防护，具备安全改动条件；(b) 测试集无标签的事实使签名带过拟合（C03 ±1kW、C05 签名带、C06 TRAIN 标记）成为最大隐藏评分敞口。
2. **解禁新边界**：所有判据改动必须 ①可解释（变量 + 时间窗 + 判断依据三要素）；②通过哨兵门禁（F1 不回退、N01-N07 误报不升、|ΔF1| ≤ 0.012）。
3. **用户已确认的两项策略决策**：算法侧**全力引入 ML**（规则稳健化 + LightGBM 混合双泳道，02 号文档）；助手侧**接入 StepFun 云端 LLM**（证据驱动 + 受限 NLU 之上的增强层，带离线降级，03 号文档）。
4. **企业 0 答复**：全方案采用"待确认 + 内部保守默认口径"双轨（07 号文档）；禁止任何"按企业要求"表述。

## §6 变更纪律（全员必读）

1. **SHA 证据只对 clean commit 有效**：提交任何文档都会改变候选 SHA → 文档提交后必须重新生成 ignored 证据；**不能把文档提交前的 SHA 当最终值**。
2. `packages/h2-contracts` 与 `packages/h2-vocabulary` 是唯一事实源：改契约/词汇必须过 `npm run h2:qa`，冻结 JSON 只允许加版本号与新增可选字段。
3. 双开关 = 回到纯确定性系统：`H2_ML_ENABLED=false`（检测）、`STEPFUN_API_KEY` 不注入（助手）。
4. 算法改动三件套：独立 commit + 阈值快照 + 四项指标对照表（写入校准记录块）。
5. 口径疑问一律进 07 号文档，走保守默认口径，不阻塞开发。
6. 安全红线不因迭代松动：local-first / loopback-only / 不发控制指令 / 建议必带人工确认 / LLM 不触碰检测证据复核事实 / 不构造健康度 / 不硬编码测试答案。
